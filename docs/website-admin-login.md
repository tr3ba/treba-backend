# Вход в админку с сайта

Сотрудник входит на основном сайте через существующий аккаунт. Если защита не подключена, достаточно пароля. Если подключены Google Authenticator, почта или Telegram Guard, сайт предлагает подключённые способы и принимает один выбранный способ.

В меню профиля Administrator, Manager, Moderator и Seller доступна кнопка «Адмін-панель». Она открывает `https://admin.treba.duckdns.org` без повторного ввода пароля. Покупателю кнопка недоступна, а сервер отклоняет создание перехода для Customer.

## Передача входа

Админка создаёт случайное состояние браузера в HttpOnly cookie и отправляет пользователя на `/shop-api/admin-entry` сайта. Сайт проверяет сессию и получает одноразовый код API. Код живёт одну минуту, хранится в базе в виде хеша, связан с текущим аккаунтом и его действующей сессией. Админка проверяет состояние браузера, обменивает код на сервере и создаёт защищённую HttpOnly cookie. Пароль и JWT не передаются в URL или localStorage сайта. Повторное погашение кода защищено проверкой конкурентного обновления.

Guard после ввода пароля связан с конкретным запросом входа. Подтвердить его можно только Telegram того же аккаунта. После подтверждения не требуется повторно проходить почту или Authenticator. Ранее существовавший отдельный QR-вход в локальной панели также сохраняется.

## Локальная разработка

По умолчанию `WebsiteLogin:Enabled` выключен. Локальный запуск и текущая форма входа AdminPanel продолжают работать отдельно. Cookie входа с сайта в этом режиме не заменяет локальную сессию. Для стенда с переходом между двумя локальными приложениями можно явно включить:

```text
WebsiteLogin__Enabled=true
WebsiteLogin__StoreOrigin=http://localhost:3034
WebsiteLogin__AdminOrigin=http://localhost:5434
ApiBaseUrl=http://127.0.0.1:5511/
```

В Next.js для такого стенда задаются `NEXT_PUBLIC_ADMIN_URL` и `TREBA_ADMIN_ORIGIN` равными адресу локальной админки. HTTP допускается только для loopback в Development. На рабочем сервере используются HTTPS origins. Публичный адрес по умолчанию — `https://admin.treba.duckdns.org`.

## Развёртывание

Миграция `20261020144055_AddWebsiteAdminLogin` добавляет необязательную связь Guard с запросом входа. Идемпотентный SQL — `scripts/sql/20261020-website-admin-login.sql`. Предыдущая схема и существующие привязки сохраняются.

Образ backend содержит отдельно опубликованную AdminPanel. Обычный deploy запускает её отдельным контейнером `treba-admin`, подключённым к Caddy через Docker network. Порт панели не публикуется на хосте. Caddy обслуживает HTTPS для `admin.treba.duckdns.org`, ключи защиты cookie сохраняются в отдельном volume. Перед переключением проверяются API и панель; старые контейнеры и конфигурация Caddy сохраняются для отката. Локальные проекты и настройки IDE этот процесс не меняет.
