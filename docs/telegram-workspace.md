# Telegram для продавца и модератора Treba

## Что реализовано

- Привязка в профиле на сайте: одноразовая ссылка `/start`, приветствие с именем, ролью и двумя ID, затем подтверждение привязки на сайте.
- Mini App для двух ролей. Продавец видит собственные товары, черновики, варианты, цены, остатки, характеристики, фотографии, импорт и профиль. Модератор видит каталог, очередь товаров, историю решений и отзывы; может публиковать или отклонять товары с обязательной причиной.
- Guard: QR на странице входа, встроенный сканер Telegram, сверка устройства и шестизначного кода, явное подтверждение входа. QR одноразовый, действует две минуты. Включённая двухфакторная проверка сохраняется.
- Импорт по HTTPS-ссылке Rozetka: название, описание, фотографии и характеристики, проверка категории, редактируемый предпросмотр, собственная цена и остаток, отправка на модерацию. До подтверждения товар не создаётся.
- «Настройки → Telegram»: сопоставления категорий Rozetka и Treba. В карточке продавца администратор задаёт разрешённые категории и включение подкатегорий.

Покупатель, администратор и менеджер не могут привязать Telegram или войти в Mini App. Администратор управляет интеграцией через сайт. Работа с заказами не добавлена.

## Локальный просмотр без бота

Запустите обычный ярлык **TREBA Admin** на рабочем столе или:

```powershell
.\scripts\Start-Treba.ps1
```

Mini App обслуживает **API**, а не Blazor-панель. При стандартных портах откройте:

- Продавец: `http://127.0.0.1:5290/telegram/?preview=Seller`
- Модератор: `http://127.0.0.1:5290/telegram/?preview=Moderator`

Порт API указан в `%LOCALAPPDATA%\Treba\launcher\session.json`. Если он занят, запускатель выбирает другой. Предпросмотр работает только в Development, использует демонстрационные данные и отключает изменения. На экране импорта есть кнопка «Показать пример предпросмотра». В Production демонстрационного API нет.

При открытии показывается фирменный экран Treba с вращающимся кольцом вокруг логотипа. Он исчезает после загрузки панели; при ошибке открывается объяснение, а не бесконечный индикатор. Для отдельного просмотра экрана используйте `http://127.0.0.1:5290/telegram/?preview=Seller&screen=loading`. Этот режим требует Development API предпросмотра. При системной настройке уменьшения анимации кольцо остаётся статичным.

Аватарка для BotFather: `assets/telegram/treba-bot-avatar.png`. Она использует существующий знак Treba и подготовлена для круглой обрезки.

## Подключение настоящего бота

1. Создайте бота в официальном **@BotFather** командой `/newbot`, сохраните username и токен локально.
2. Подготовьте публичный HTTPS-адрес API, например `https://api.example.com/telegram/`. По тому же адресу должны быть доступны `/api/telegram/*` и `/api/v1/products/*`. При обратном прокси путь `/telegram/` нужно сохранить. Для удалённых фотографий нужен существующий маршрут `/uploads/products/*`.
3. В BotFather настройте Main Mini App или кнопку меню на этот HTTPS-адрес. Рабочие кнопки в сообщении и меню чата также устанавливаются ботом.
4. Примените миграцию `20261018112728_AddTelegramWorkspace`, если она ещё не применена. Готовый идемпотентный SQL: `scripts/sql/20261018-telegram-workspace.sql`. Он создаёт семь таблиц и переносит в разрешения точные категории существующих товаров активных продавцов, без автоматического доступа ко всем подкатегориям.
5. Выполните из корня репозитория:

```powershell
.\scripts\Configure-TrebaTelegram.ps1 `
    -BotUsername 'your_treba_bot' `
    -MiniAppUrl 'https://api.example.com/telegram/' `
    -Enable
```

Токен вводится в скрытом локальном приглашении. Скрипт сохраняет его в .NET User Secrets текущего пользователя; остальные параметры — в игнорируемом `WebApi/appsettings.Development.json`. Передавать токен в чат, коммит или аргумент командной строки не нужно.

6. Повторно запустите **TREBA Admin**. Запускатель учитывает изменение локальных секретов и перезапускает принадлежащие ему API и панель. Сервер запрашивает обновления через long polling: отдельный процесс бота не нужен. Для одного бота PostgreSQL разрешает только одному экземпляру API читать обновления.
7. Через учётную запись администратора откройте «Настройки → Telegram», задайте сопоставления `c12345 → категория Treba`, затем проверьте категории в карточках продавцов.
8. Войдите продавцом или модератором, откройте профиль, нажмите «Привязать Telegram», выполните `/start`, вернитесь на сайт и подтвердите отображённый Telegram. После `/menu` бот покажет Mini App и Guard.

Без `-Enable` настройка сохраняется в отключённом состоянии. Для отключения работающего бота повторите команду без этого флага и перезапустите запускатель. Если у бота ранее был webhook, удалите его перед использованием long polling через официальный Bot API.

### Настройки сервера

На сервере вместо локального скрипта задайте секреты через среду развёртывания:

```text
Telegram__Enabled=true
Telegram__LongPollingEnabled=true
Telegram__BotUsername=your_treba_bot
Telegram__BotToken=<secret supplied by deployment environment>
Telegram__MiniAppUrl=https://api.example.com/telegram/
Telegram__EnforceSellerCategories=true
```

User Secrets предназначены для локальной разработки. Не добавляйте токен в общий `appsettings.json`.

## Если из Telegram открывается магазин

Для `@treba_marketplace_bot` Main Mini App и Menu Button должны указывать ровно на `https://treba.duckdns.org/telegram/`. Время сообщения вроде `13:37` частью адреса не является. Эти настройки в Telegram независимы; старые кнопки в сообщениях также содержат свой URL. После изменения серверной настройки отправьте боту `/menu`, чтобы получить новые кнопки.

Проверьте доступность размещённого приложения:

```powershell
.\scripts\Test-TrebaTelegramHosting.ps1
```

Проверка ничего не меняет, не требует токена и отличает HTML магазина от Mini App. Она также проверяет JavaScript, стили, знак проекта и публичную конфигурацию Telegram. Код завершения `1` означает проблему публикации или маршрутов, `2` — размещённый Mini App с незавершёнными настройками бота, `0` — согласованные настройки сервера. Доступность Telegram и работоспособность конкретного аккаунта эта проверка не подтверждает.

На сервере нужно отдельно проверить `http://127.0.0.1:5000/telegram/` и `http://127.0.0.1:5000/api/telegram/configuration`. Если они возвращают 404, требуется обновление WebApi с нашей интеграцией. Если напрямую API отвечает правильно, а публичный адрес выдаёт магазин или 404, нужно исправить маршрутизацию обратного прокси. Шаблон для существующего HTTPS-блока Nginx: `scripts/server/telegram-mini-app.nginx.conf.example`. Перед применением проверьте реальный upstream и действующую конфигурацию; файл не запускает развёртывание и не меняет сервер автоматически.

Проверка AWS от 19 октября подтвердила 404 на обоих прямых маршрутах API и отсутствие у `treba-sasha` доступа к Docker и `sudo`. Готовая передача владельцу сервера с порядком публикации, сверкой БД, маршрутизацией и проверками: [telegram-server-handoff.md](telegram-server-handoff.md). Смена URL в BotFather без публикации кода эту ситуацию не исправит.

В окружении API должны совпадать:

```text
Telegram__Enabled=true
Telegram__LongPollingEnabled=true
Telegram__BotUsername=treba_marketplace_bot
Telegram__MiniAppUrl=https://treba.duckdns.org/telegram/
```

Токен задаётся отдельно в серверном хранилище секретов. После запуска обновлённый worker устанавливает Menu Button на `MiniAppUrl`. URL Main Mini App в BotFather настраивается отдельно: `/mybots` → нужный бот → Bot Settings → Configure Mini App. URL кнопки меню: Bot Settings → Menu Button. Успешная публикация означает, что `/telegram/` отдаёт рабочую панель, `/api/telegram/configuration` возвращает её настройки и бот открывает тот же адрес.

## Разрешения и импорт

Импорт сначала определяет исходную категорию Rozetka по breadcrumbs. Произвольный выбор категории вместо категории источника не разрешён. Если сопоставления или доступа нет, импорт блокируется с объяснением. Проверка повторяется при отправке предпросмотра: отзыв разрешения, отключение категории или смена сопоставления не обходятся уже открытым экраном.

Пустой список разрешений означает отсутствие доступа. Неактивные категории и категории с неактивным родителем не разрешаются. При включённом `Telegram:Enabled` и `EnforceSellerCategories` ограничения также действуют при сохранении и отправке товаров через сайт.

Предпросмотр хранится один час, одновременно разрешено до десяти незавершённых импортов. Повторное подтверждение возвращает ID того же товара. Повторный импорт уже отправленного товара тем же продавцом блокируется.

Поддерживаются публичные HTTPS-страницы товаров Rozetka `/p123456/`, JSON-LD и метаданные страницы, до восьми фотографий по пять МБ. Сетевой клиент проверяет адреса и перенаправления, ограничивает размер и время загрузки. Описания преобразуются в обычный текст. Цена источника служит начальным значением: продавец проверяет и указывает свою цену.

**Ограничения для первого реального запуска:**

- На проверенной живой странице Rozetka возвращала HTTP 403 / Cloudflare. Обход защиты не выполняется. В таком случае интерфейс предлагает повторить позже или добавить товар вручную; стабильность импорта конкретных страниц зависит от доступности источника.
- Запись фотографий в общее SFTP-хранилище требует ранее запрошенных серверных прав. Эти права пока выясняются отдельно. При ошибке сохранения импорт откатывает товар, варианты и метаданные и удаляет созданные им файлы; отправка не выдаётся за успешную.
- Настоящие `/start`, камера Telegram и подтверждение входа с телефона проверяются после создания бота и настройки публичного HTTPS. До этого доступны локальные экраны и автоматические интеграционные проверки.

## Проверка реализации

```powershell
dotnet test tests/WebApi.Tests/WebApi.Tests.csproj -c Release
.\tests\Launcher.Tests.ps1
```

Для PostgreSQL-проверок задайте `TREBA_TEST_POSTGRES` локальной строкой подключения. Тесты создают собственные таблицы с уникальным префиксом и удаляют только принадлежащие тесту таблицы. Проверяются подпись Telegram, сроки действия, роли, подтверждение привязки, отзыв доступа, область продавца, двухфакторная проверка, повторные запросы, конкурентное завершение Guard и откат импорта при ошибке хранилища.

Официальная документация: [Mini Apps и проверка initData](https://core.telegram.org/bots/webapps), [возможности и deep links ботов](https://core.telegram.org/bots/features).
