# Telegram для продавца и модератора Treba

## Что реализовано

- Привязка в профиле на сайте: одноразовая ссылка `/start`, приветствие с именем, ролью и двумя ID, затем подтверждение привязки на сайте.
- Mini App для двух ролей. Продавец видит собственные товары, черновики, варианты, цены, остатки, характеристики, фотографии, импорт и профиль. Модератор видит каталог, очередь товаров, историю решений и отзывы; может публиковать или отклонять товары с обязательной причиной.
- Guard: QR на странице входа, встроенный сканер Telegram, сверка устройства и шестизначного кода, явное подтверждение входа. QR одноразовый, действует две минуты. Включённая двухфакторная проверка сохраняется.
- Импорт по HTTPS-ссылке Rozetka: название, описание, фотографии и характеристики, проверка категории, редактируемый предпросмотр, собственная цена и остаток, отправка на модерацию. До подтверждения товар не создаётся.
- «Настройки → Telegram»: сопоставления категорий Rozetka и Treba. В карточке продавца администратор задаёт разрешённые категории и включение подкатегорий.

Покупатель, администратор и менеджер не могут привязать Telegram или войти в Mini App. Администратор управляет интеграцией через сайт. Работа с заказами не добавлена.

## Локальный просмотр без бота

Для локального демонстрационного API запустите режим разработки:

```powershell
.\scripts\Start-Treba.ps1 -LocalApi
```

Mini App обслуживает **API**, а не Blazor-панель. При стандартных портах откройте:

- Продавец: `http://127.0.0.1:5290/telegram/?preview=Seller`
- Модератор: `http://127.0.0.1:5290/telegram/?preview=Moderator`

Порт API указан в `%LOCALAPPDATA%\Treba\launcher\session.json`. Если он занят, запускатель выбирает другой. Предпросмотр работает только в Development, использует демонстрационные данные и отключает изменения. На экране импорта есть кнопка «Показать пример предпросмотра». В Production демонстрационного API нет.

При открытии показывается фирменный экран Treba с вращающимся кольцом вокруг логотипа. Он исчезает после загрузки панели; при ошибке открывается объяснение, а не бесконечный индикатор. Для отдельного просмотра экрана используйте `http://127.0.0.1:5290/telegram/?preview=Seller&screen=loading`. Этот режим требует Development API предпросмотра. При системной настройке уменьшения анимации кольцо остаётся статичным.

Аватарка для BotFather: `assets/telegram/treba-bot-avatar.png`. Она использует существующий знак Treba и подготовлена для круглой обрезки.

## Подключение настоящего бота

Для уже размещённого `@treba_marketplace_bot` откройте обычный ярлык **TREBA Admin**
на рабочем столе или `scripts/Start-Treba.ps1`. Админка использует серверный API с настроенным ботом.
Войдите продавцом/модератором и начните привязку в профиле. Ссылка на бота появится в том же блоке,
Telegram откроется в отдельной вкладке. После `/start` профиль автоматически покажет подтверждение
найденного Telegram. Отдельная админка Online и ручное обновление статуса не требуются.
Если Telegram уже привязан, профиль показывает аккаунт без инструкций по привязке.
Режим разработки `-LocalApi` использует собственные настройки и автоматически серверный токен не получает.

1. Создайте бота в официальном **@BotFather** командой `/newbot`, сохраните username и токен локально.
2. Подготовьте публичный HTTPS-адрес API, например `https://api.example.com/telegram/`. По тому же адресу должны быть доступны `/api/telegram/*` и `/api/v1/products/*`. При обратном прокси путь `/telegram/` нужно сохранить. Для удалённых фотографий нужен существующий маршрут `/uploads/products/*`.
3. В BotFather настройте Main Mini App или кнопку меню на этот HTTPS-адрес. Рабочие кнопки в сообщении и меню чата также устанавливаются ботом.
4. Примените миграцию `20261018112728_AddTelegramWorkspace`, если она ещё не применена. Готовый идемпотентный SQL: `scripts/sql/20261018-telegram-workspace.sql`. Он создаёт семь таблиц и переносит в разрешения точные категории существующих товаров активных продавцов, без автоматического доступа ко всем подкатегориям.
5. Выполните из корня репозитория:

```powershell
.\scripts\Configure-TrebaTelegram.ps1 `
    -BotUsername 'your_treba_bot' `
    -MiniAppUrl 'https://api.example.com/telegram/' `
    -Enable
```

Токен вводится в скрытом локальном приглашении. Скрипт сохраняет его в .NET User Secrets текущего пользователя; остальные параметры — в игнорируемом `WebApi/appsettings.Development.json`. Передавать токен в чат, коммит или аргумент командной строки не нужно.

6. Если вы настраивали собственный локальный API, повторно запустите `scripts/Start-Treba.ps1 -LocalApi`. Запускатель учитывает изменение локальных секретов и перезапускает принадлежащие ему API и панель. Сервер запрашивает обновления через long polling: отдельный процесс бота не нужен. Для одного бота PostgreSQL разрешает только одному экземпляру API читать обновления.
7. Через учётную запись администратора откройте «Настройки → Telegram», задайте сопоставления `c12345 → категория Treba`, затем проверьте категории в карточках продавцов.
8. Войдите продавцом или модератором, откройте профиль, нажмите «Привязать Telegram» → «Открыть Telegram» и выполните `/start`. Профиль остаётся открытым и автоматически покажет найденный аккаунт для подтверждения. После `/menu` бот покажет Mini App и Guard.

Без `-Enable` настройка сохраняется в отключённом состоянии. Для отключения работающего бота повторите команду без этого флага и перезапустите запускатель. Если у бота ранее был webhook, удалите его перед использованием long polling через официальный Bot API.

### Настройки сервера

На сервере вместо локального скрипта задайте секреты через среду развёртывания:

```text
Telegram__Enabled=true
Telegram__LongPollingEnabled=true
Telegram__BotUsername=your_treba_bot
Telegram__BotToken=<secret supplied by deployment environment>
Telegram__MiniAppUrl=https://api.example.com/telegram/
Telegram__EnforceSellerCategories=true
```

User Secrets предназначены для локальной разработки. Не добавляйте токен в общий `appsettings.json`.

## Если из Telegram открывается магазин

Для `@treba_marketplace_bot` Main Mini App и Menu Button должны указывать ровно на `https://treba.duckdns.org/telegram/`. Время сообщения вроде `13:37` частью адреса не является. Эти настройки в Telegram независимы; старые кнопки в сообщениях также содержат свой URL. После изменения серверной настройки отправьте боту `/menu`, чтобы получить новые кнопки.

Проверьте доступность размещённого приложения:

```powershell
.\scripts\Test-TrebaTelegramHosting.ps1
```

Проверка ничего не меняет, не требует токена и отличает HTML магазина от Mini App. Она также проверяет JavaScript, стили, знак проекта и публичную конфигурацию Telegram. Код завершения `1` означает проблему публикации или маршрутов, `2` — размещённый Mini App с незавершёнными настройками бота, `0` — согласованные настройки сервера. Доступность Telegram и работоспособность конкретного аккаунта эта проверка не подтверждает.

На сервере нужно отдельно проверить `http://127.0.0.1:5000/telegram/` и `http://127.0.0.1:5000/api/telegram/configuration`. Если они возвращают 404, требуется обновление WebApi с нашей интеграцией. Если напрямую API отвечает правильно, а публичный адрес выдаёт магазин или 404, нужно исправить маршрутизацию обратного прокси. Шаблон для существующего HTTPS-блока Nginx: `scripts/server/telegram-mini-app.nginx.conf.example`. Перед применением проверьте реальный upstream и действующую конфигурацию; файл не запускает развёртывание и не меняет сервер автоматически.

19 октября интеграция опубликована через штатный GitHub Actions / AWS SSM: `/telegram/` отдаёт Mini App, публичная конфигурация подтверждает `@treba_marketplace_bot`, меню бота указывает на `/telegram/`. Исторические инструкции для владельца сервера остаются в [telegram-server-handoff.md](telegram-server-handoff.md). Админка и бот используют один серверный API; локальный API для обычной работы запускать не требуется.

В окружении API должны совпадать:

```text
Telegram__Enabled=true
Telegram__LongPollingEnabled=true
Telegram__BotUsername=treba_marketplace_bot
Telegram__MiniAppUrl=https://treba.duckdns.org/telegram/
```

Токен задаётся отдельно в серверном хранилище секретов. После запуска обновлённый worker устанавливает Menu Button на `MiniAppUrl`. URL Main Mini App в BotFather настраивается отдельно: `/mybots` → нужный бот → Bot Settings → Configure Mini App. URL кнопки меню: Bot Settings → Menu Button. Успешная публикация означает, что `/telegram/` отдаёт рабочую панель, `/api/telegram/configuration` возвращает её настройки и бот открывает тот же адрес.

## Разрешения и импорт

Поддерживаются ссылки на конкретные товары Rozetka, Prom.ua и «Эпицентра». Rozetka сначала загружается через публичный API товара; при недоступности API используется HTML. Для остальных источников читаются доступные данные страницы. До восьми фотографий по пять МБ, описание и характеристики попадают в предпросмотр; карточка публикуется только после решения модератора. Сетевая защита источника может временно препятствовать загрузке: очередь позволяет повторить запрос, ручное создание остаётся доступным.

Продавцу нужны активный аккаунт, профиль и магазин, разрешения на категорию. Сопоставления исходных категорий имеют приоритет; продавец с доступом ко всему каталогу может указать разрешённую категорию для неопределённого источника. Ограничения повторно проверяются при отправке. Пустые разрешения, отключённая категория или её родитель блокируют импорт. Выбор всех текущих категорий охватывает их будущих потомков; новую корневую категорию нужно разрешить отдельно.

## Рабочие инструменты продавца

1. **Создание продавца:** «Продавцы → Создать продавца» доступно администратору. Одной транзакцией создаются аккаунт, профиль, магазин и категории. По умолчанию профиль ожидает проверки; немедленная активация включается явно. Тестовый режим создаёт реквизит `TEST-…` и явное описание. Пароль 12–128 символов, хранится только хеш, в локальные черновики не попадает.
2. **Уведомления:** новая отправка товара на модерацию создаёт сообщение для привязанных активных модераторов; одобрение и отклонение с причиной — для привязанного продавца. Кнопка открывает карточку в Mini App. Решение и запись уведомления сохраняются вместе. Перед доставкой проверяются актуальные роль, привязка, доступ и статус товара. События до обновления не рассылаются. Сетевые ошибки повторяются до пяти попыток, HTTP 400/403 завершает доставку. При потере сетевого подтверждения уже принятого Telegram сообщения возможен повтор.
3. **Очередь импорта:** до 20 ссылок в одном запросе, до 50 незавершённых импортов. Загрузка продолжается на сервере после закрытия Telegram. Два обработчика, восстановление прерванных заданий по трёхминутной аренде, отдельный повтор неудачных загрузок. Одинаковые незавершённые ссылки с той же категорией переиспользуются. История показывает последние 100 заданий. Готовый предпросмотр действует один час; истёкший можно загрузить заново. Ничего не публикуется автоматически.
4. **Автосохранение:** поля редактора и выбранные фотографии сохраняются в IndexedDB того же браузера отдельно для пользователя и карточки. В админке проверка раз в две секунды, в Mini App — после паузы ввода. При возвращении предлагается восстановление или удаление копии. Копия удаляется после успешного сохранения; при частичной загрузке сохраняются ID созданного товара и оставшиеся фото. Очистка данных браузера удаляет копию; между устройствами она не переносится. Ограничения браузера на хранилище отображаются в интерфейсе. При восстановлении существующего товара сохраняется серверная проверка версии.
5. **Массовые изменения:** выберите товары в каталоге админки или Mini App. Фиксированная цена или процент, остаток и доступность вариантов показываются до подтверждения. Если новая цена достигает старой зачёркнутой цены, её удаление также видно в предпросмотре. До 100 товаров / 500 вариантов за операцию. Подписанный план действует десять минут, привязан к пользователю и области продавца; изменение карточек, прав или повторное применение требуют нового предпросмотра. Сохранение атомарное, действия попадают в существующий журнал. Товары на модерации и в архиве недоступны; статус публикации сохраняется. После перезапуска API старый план может потребовать повторной подготовки.
6. **Поиск дублей:** по штрихкоду либо сочетанию бренда и артикула производителя (MPN), в том числе между источниками. Продавец видит совпадения в своих магазинах, администратор — в каталоге. Из импортированных данных идентификаторы извлекаются при наличии у источника; в редакторе их можно заполнить вручную. Предупреждение позволяет открыть существующий товар или подтвердить отдельную карточку. Автоматического объединения нет; для старых карточек без идентификаторов совпадение не определяется.

Фоновый обработчик включён по умолчанию (`Telegram:WorkspaceJobsEnabled=true`) и работает с PostgreSQL. Для уведомлений дополнительно требуется настроенный бот; очередь импорта не зависит от токена. Для локальных тестовых стендов обработчик можно отключить этой настройкой.

## Схема и публикация

Перед запуском версии с рабочими инструментами выполните идемпотентный `scripts/sql/20261019-seller-workspace.sql` в нужной базе. Он создаёт только `product_identities`, `seller_import_jobs`, `telegram_notifications`, добавляет историю миграции и копирует CRUD-права существующих ролей приложения с таблицы импортов. На проверенной базе `treba_dev` скрипт применён 19 октября. Проверка перед развёртыванием требует эту миграцию и доступ к новым таблицам до остановки предыдущей версии API.

Настоящие `/start`, камера Telegram и подтверждение Guard проверяются с привязанного аккаунта на телефоне. Автоматические проверки и браузерный стенд используют тестового клиента бота, не рассылают сообщения настоящим пользователям.

## Проверка реализации

```powershell
dotnet test src/Rozetka-clone/WebApi.Tests/WebApi.Tests.csproj -c Release
.\tests\Launcher.Tests.ps1
```

Для PostgreSQL-проверок задайте `TREBA_TEST_POSTGRES` локальной строкой подключения. Тесты создают собственные таблицы с уникальным префиксом и удаляют только принадлежащие тесту таблицы. Проверяются подпись Telegram, сроки действия, роли, подтверждение привязки, отзыв доступа, область продавца, двухфакторная проверка, повторные запросы, конкурентное завершение Guard и откат импорта при ошибке хранилища.

Официальная документация: [Mini Apps и проверка initData](https://core.telegram.org/bots/webapps), [возможности и deep links ботов](https://core.telegram.org/bots/features).
