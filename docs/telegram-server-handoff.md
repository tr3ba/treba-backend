# Передача Telegram-интеграции на сервер Treba

Бот: `@treba_marketplace_bot`. Публичный адрес Mini App: **https://treba.duckdns.org/telegram/**.

## Что проверено 19 октября 2026

Интерактивная SSH-проверка под `treba-sasha` завершилась успешно:

| Проверка на AWS-сервере | Результат |
| --- | --- |
| `http://127.0.0.1:5000/ping` | 200 |
| `http://127.0.0.1:5000/telegram/` | 404 |
| `http://127.0.0.1:5000/api/telegram/configuration` | 404 |
| Доступ `treba-sasha` к Docker | Отказ |
| Разрешения `sudo` у `treba-sasha` | Отсутствуют |

Публичный `/telegram/` обслуживает Next.js и возвращает страницу магазина с HTTP 404. Работающий WebApi также не содержит Telegram-модуля. Поэтому одного изменения ссылки в BotFather недостаточно: нужны публикация кода и маршрутизация Mini App на обновлённый API.

Через SSH действующую конфигурацию прокси и контейнера прочитать не удалось. Последующая проверка через штатный AWS SSM подтвердила Caddy в контейнере `treba-caddy`, конфигурацию `/opt/treba-caddy/Caddyfile` и backend upstream `host.docker.internal:5000`. Переменные Telegram уже есть в `/home/ubuntu/treba-backend.env`, но отсутствуют в окружении работающего контейнера. Значения секретов при проверке не выводятся.

## Автоматический выпуск через существующий CI/CD

Для выпуска подготовлен `scripts/server/deploy-telegram-backend.sh`; его запускает обновлённый `Deploy Backend to EC2` через существующий AWS SSM. Развёртывается образ с тегом SHA проверенного коммита. Перед переключением запускаются отдельная CLI-проверка БД/бота и временный контейнер на случайном loopback-порту без чтения Telegram updates. В Caddy `/telegram` и `/telegram/*` добавляются в проверенный существующий API matcher, затем конфигурация проверяется и перезагружается. Предыдущий контейнер и конфигурация сохраняются; при ошибке выполняется откат.

Команда `dotnet WebApi.dll --check-telegram-deployment` только проверяет миграции, `getMe` и отсутствие webhook. Она не открывает HTTP, не изменяет БД, не отправляет сообщения и не запускает long polling. Проверка не заменяет тест на телефоне. `@` перед username из BotFather нормализуется приложением.

В CI добавлена отдельная PostgreSQL 18 для интеграционных тестов. Сборка образа проходит эти тесты перед публикацией. Тег `latest` обновляется только из `main`; сервер использует неизменяемый тег SHA.

Для повторного выпуска уже проверенного образа вручную запустить `Deploy Backend to EC2` с `image_revision`, равным полному SHA его коммита. Код сценария берётся из выбранной ветки workflow, образ — из указанного неизменяемого тега. При изменениях только сценария выпуска пересборка приложения не требуется. Финальная проверка ждёт меню до минуты с учётом 15-секундного повтора worker. При неудаче сохраняется остановленный контейнер `treba-backend-failed-*`; выводятся только безопасные диагностические сообщения Telegram, без токена и сообщений пользователей.

## 1. Подготовить код к публикации

Ветка интеграции: `feat/admin-sellers-reviews-dashboard`. База первоначального пакета передачи: `bbc66957cf72bec399b4ee6886fd83ca92f72417`. Актуальное состояние публикации нужно смотреть в PR и GitHub Actions.

Пакет передачи содержит `treba-admin-telegram.patch` с полным набором текущих изменений админки и Telegram, включая новые файлы и тесты. Telegram использует общие изменения каталога, авторизации и хранения фотографий, поэтому копирования одного каталога `wwwroot/telegram` недостаточно. Локальные пароли, User Secrets, настройки Development, SSH-ключи и результаты сборки в пакет не включены. Список файлов и SHA-256 находятся в `manifest.json`.

Применять патч следует в отдельном checkout/ветке для проверки, а затем включать изменения в актуальную командную версию через обычный процесс ревью:

```bash
git apply --check /path/to/treba-admin-telegram.patch
git apply /path/to/treba-admin-telegram.patch
dotnet build src/Rozetka-clone/Rozetka-clone.sln -c Release
dotnet test src/Rozetka-clone/WebApi.Tests/WebApi.Tests.csproj -c Release
```

Патч не содержит новые файлы управления заказами или оплатой. В общей БД ранее обнаружена миграция `20261017144804_AddPayment`, отсутствующая в этой локальной версии. Перед выпуском нужно согласовать код с её владельцем и сохранить изменения коллег. Если `git apply --check` сообщает конфликт, сначала объединить изменения в исходниках; не перезаписывать работающую версию набором локальных DLL.

## 2. Сверить БД и окружение API

Для Telegram нужна миграция `20261018112728_AddTelegramWorkspace`. В общей `treba_dev` она уже была применена 18 октября; администратор должен сверить **БД действующего контейнера**, не раскрывая строку подключения. Для другой БД готов идемпотентный `scripts/sql/20261018-telegram-workspace.sql`.

Админка также использует `20261017110000_AddAdminAuditLog`. Скрипт `scripts/sql/20261017-admin-audit-log.sql` выполнять только при отсутствии этой миграции: он не идемпотентный. Не удалять историю миграций и не откатывать чужие миграции. Автоматическое применение через `ApplyMigrations` не заменяет сверку общей схемы.

В серверном окружении WebApi установить:

```text
Telegram__Enabled=true
Telegram__LongPollingEnabled=true
Telegram__BotUsername=treba_marketplace_bot
Telegram__MiniAppUrl=https://treba.duckdns.org/telegram/
Telegram__EnforceSellerCategories=true
```

`Telegram__BotToken` владелец добавляет из серверного хранилища секретов. Токен не передавать в патче, чате, отчёте или аргументах командной строки. Сохранить действующие настройки БД, JWT, шифрования и загрузок.

Для одного бота использовать один способ получения обновлений: здесь реализован long polling. Если другой процесс уже обслуживает этот токен, владелец должен согласованно остановить прежний обработчик; при установленном webhook — удалить его через официальный Bot API. Существующие локальные настройки бота автоматически на AWS не переносятся.

## 3. Развернуть WebApi и админку

Штатная цепочка репозитория: `Docker Build and Push to ECR` → `Deploy Backend to EC2` → AWS SSM → контейнер `treba-backend`, порт `5000`. Dockerfile: `docker/Dockerfile.backend`. В workflow указаны env-файл `/home/ubuntu/treba-backend.env` и том `/opt/treba-backend/uploads:/app/wwwroot/uploads`.

Проверить реальные параметры и сохранить предыдущую версию образа/конфигурации для отката до запуска развёртывания. Сам ручной запуск Deploy без предварительной сборки нового кода лишь повторно запустит старый образ. Публикацию выполняет владелец через существующий CI/CD или свой административный доступ; предоставлять разработчику общий `sudo` или доступ к Docker для этого не требуется.

Backend workflow не публикует Blazor AdminPanel: её обновить используемым в проекте способом вместе с WebApi, чтобы в профиле появились привязка Telegram и Guard на странице входа. Публичный Mini App обслуживает сам WebApi; он не является страницей Blazor или Next.js.

Сразу после обновления на сервере должны успешно отвечать:

```bash
curl -fsS http://127.0.0.1:5000/ping
curl -fsS http://127.0.0.1:5000/telegram/ >/dev/null
curl -fsS http://127.0.0.1:5000/api/telegram/configuration
```

Последний запрос возвращает только публичные параметры, без токена. Ожидаются `configured: true`, правильные `botUsername` и `miniAppUrl`. Если прямой API по-прежнему выдаёт 404, публикация новой версии ещё не состоялась.

## 4. Настроить HTTPS-прокси и Telegram

Для `treba.duckdns.org` направить `/telegram/` в тот же WebApi, что обслуживает `/api/telegram/`, `/api/v1/` и фотографии `/uploads/products/`. Сохранять исходный путь запроса. Магазин продолжает обслуживать `/`.

Для проверенного Caddy есть `scripts/server/telegram-mini-app.Caddyfile.example`; автоматический выпуск меняет только path matcher в существующем файле. Для другого окружения с Nginx оставлен `scripts/server/telegram-mini-app.nginx.conf.example`. Существующий маршрут `/api/` уже может правильно обслуживать Telegram API — не создавать дубликаты. Перед reload проверять собранный конфиг соответствующим прокси и сохранять предыдущую версию.

В BotFather отдельно проверить **Main Mini App** и **Menu Button**: оба должны вести на `https://treba.duckdns.org/telegram/`, без `13:37`. После включения worker обновляет Menu Button; Main Mini App задаётся в BotFather. Старые сообщения не изменятся — получить новые кнопки командой `/menu`.

## 5. Подтвердить результат

На компьютере разработчика:

```powershell
.\scripts\Test-TrebaTelegramHosting.ps1
```

Код `0` означает доступность HTML/JS/CSS/логотипа и согласованные публичные настройки API. Проверка не вызывает изменения и не подтверждает работу реального Telegram-аккаунта.

Затем продавцом или модератором: профиль сайта → «Привязать Telegram» → `/start` → подтверждение привязки на сайте → `/menu` → Mini App. Отдельно проверить Guard с QR страницы входа и подтверждением кода. Камеру и вход с телефона нужно проверить в настоящем Telegram.

Права на запись фотографий рассматриваются отдельно; успешная публикация Mini App не доказывает работоспособность сохранения фотографий. Доступность страниц Rozetka также зависит от ограничений источника.

При проблеме после выпуска вернуть прежний образ и конфигурацию прокси/окружения из сохранённой версии. Добавленные таблицы автоматически не удалять.
